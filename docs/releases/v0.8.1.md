Structured logging overhaul. Thane's logging system now writes JSON by default, self-manages rotation, propagates trace context through the agent loop, and indexes every log record in SQLite for fast session-scoped queries from the web dashboard.

**37 files changed, 2,783 insertions, 230 deletions across 10 commits.**

## Highlights

### Self-Managed Log Rotation (#521)
- JSON-structured log output by default — machine-parseable, human-readable with `jq`
- Built-in file rotation with configurable max size, backup count, and optional gzip compression
- Replaces external logrotate dependency — Thane manages its own log lifecycle
- Configurable via `logging:` block in config.yaml (`dir`, `max_size_mb`, `max_backups`, `compress`)

### Context-Propagated Logging (#522)
- Automatic `session_id`, `conversation_id`, `subsystem`, `tool`, and `model` fields on every log record
- Context values flow through the full agent loop — from request intake through tool execution to response
- `logging.With(ctx, "key", "value")` for ad-hoc context enrichment
- Subsystem constants (`agent`, `api`, `delegate`, `metacog`, `scheduler`, `signal`) for consistent filtering

### SQLite Log Index (#523)
- Every log record dual-written to indexed SQLite columns alongside raw log files
- Queryable by session, conversation, subsystem, tool, model, and level
- Async batch writer with configurable flush interval — no impact on hot path latency
- `normalizeLevel()` maps custom `slog.Level` values (e.g., TRACE) to human-readable strings

### Session Log Viewer (#525)
- "Session Logs" card on the web dashboard session detail page
- HTMX-powered lazy loading — doesn't slow down the initial page render
- Inline filters for level (TRACE through ERROR) and subsystem
- Expandable attribute details per log entry, source file references
- Directly linked to the existing session inspector

### Log Index Retention (#525)
- Configurable retention policy for DEBUG/TRACE entries (`retention_days`, default: 7)
- INFO and above kept indefinitely
- Background pruner runs on startup and every 24 hours
- Set `retention_days: 0` to disable pruning entirely

## Bug Fixes

- **Nil-interface panic** (#526): `newLogStore(nil)` returned `*logStoreAdapter(nil)` which wrapped as a non-nil interface, causing the session log viewer to panic when no log index was configured. Fixed by returning the `web.LogStore` interface type directly.
- **normalizeLevel for TRACE** (#525): Custom `slog.Level(-8)` rendered as "DEBUG-4" instead of "TRACE". Added `normalizeLevel()` to map all custom levels correctly.
- **UTC timestamp normalization** (#525): Log index timestamps stored in local time caused unreliable retention pruning and lexicographic comparisons. All timestamps now normalized to UTC.
- **Subsystem filter mismatch** (#525): Web dashboard subsystem dropdown used stale values (`metacognitive`, `tool`) that didn't match actual logging constants (`metacog`, `scheduler`).
