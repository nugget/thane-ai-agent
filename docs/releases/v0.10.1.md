# v0.10.1 — The Provenance Release

v0.10.0 turned the loop graph into something the model could finally see. v0.10.1 is about being able to *trust* what everyone — operator, model, and remote collaborators — can now see and touch. The document substrate becomes co-authored and provable: signed by known keys, synced fast-forward-only from an operator remote, and auditable down to the individual revision. The same provenance discipline reaches the loop graph, and alongside it, a running audit of what the model actually reads each turn made the agent's working mind smaller, truer, and cheaper.

## The Document Substrate Becomes Co-Authored and Provable

The largest arc in this release: a secure document root is no longer a single-author store. An operator can now co-author thane's high-integrity documents from a workstation, through a shared bare remote, without weakening the trust model.

- **Operator allowed signers.** Document roots gain an out-of-tree trust anchor: a fail-closed allowed-signers configuration naming exactly which keys may author commits in a signed root. Rendering, reconciliation, and a boot-time verify-commit round-trip guarantee the root's history checks out against those keys before thane will build on it. (#1138, #1139, #1140, #1135)
- **Fast-forward-only remote sync.** A document root can declare an optional `git.remote`; thane fetches, verifies the incoming range against the allowed signers, and applies fast-forwards only. The remote is treated as untrusted transport — trust lives in the signatures, never the channel. If the remote rewinds or diverges, the sync engine refuses with no side effects and reports why; resolution belongs to the operator, and thane never force-pushes over anything. Sync-state transitions wake the core loop so the assistant knows its substrate moved. (#1143, #1144, #1146, #1147, #1148, #1149, #1154, #1137)
- **Revision forensics for the model.** New `doc_history`, `doc_diff`, and `doc_at` tools let the model read a document's git history the way an engineer would — who changed what, when, verified against which signer — with untrusted revisions honestly quarantined under `unverified_body` so they can't be pattern-matched as normal reads. This shipped the audit trail that made two production loop-health investigations this cycle take minutes instead of hours. (#1141, #1142, #1136)
- **One checkout primitive under everything.** The mirror/signed/verified checkout lifecycle was extracted into a single `checkout` package, and everything that touches a working tree now routes through it: doc-root sync, core identity bootstrap, and forge project subscriptions, which can now maintain a local read-only mirror of a watched repository so loops read source without network calls. One primitive, one sync-state registry, one set of semantics. (#1156, #1157, #1158, #1159, #1161, #1162, #1163)
- **No uncatalogued tools, ever again.** The revision tools initially shipped invisible to the model — registered but absent from the catalog — the third occurrence of that failure class. A CI gate and a runtime guard now make an uncatalogued native tool a build failure instead of a silent gap. (#1150)

## The Loop Graph Becomes a Managed Corpus

The #1102/#1106 program landed its structural tiers: loops now carry the same class of provenance and legibility the document corpus has.

- **Intent and origin are first-class.** `Spec.Intent` records why a loop exists in the loop's own words, and every creation stamps origin pointers — request, conversation, creating loop, timestamp — at the commit chokepoint, resolvable on demand against the primary stores rather than snapshotted. A loop can now answer "who made you and why" from structure, not folklore. (#1123, #1125)
- **One canonical view everywhere.** `LoopView` — the "ps auxwwww" projection — now backs `loop_definition_get`/`list`, spawn and stop results, and a new always-on self-context block, so a loop sees its own identity, placement, and inheritance every iteration in the same shape the operator sees. (#1126, #1127, #1128)
- **One front door for creation.** `thane_loop_create` consolidates the creation family; `thane_curate` and `thane_create_container` are removed outright rather than left as drifting synonyms. The decode boundary also tolerates stringified spec/launch arguments — a recurring model-side serialization stumble that used to bounce otherwise-valid calls. (#1129, #1130)
- **Placement is now advised, not guessed.** Tier 2 of the container-corpus design: a `loop_containers` directory answers "where should this loop live," a non-blocking placement advisory flags create-time mismatches, and the derived tree projection makes the hierarchy legible without walking IDs. The web console graph updates live on add/remove/reparent. (#1133, #1124, #1134)
- **Running loops embody their stored spec.** Retune conformance: update-tool changes to scalar knobs (sleep bounds, task text) now promote into running loops at turn boundaries instead of requiring a relaunch — closing the "edited the definition, nothing changed" trap that cost a production debugging evening this cycle. (#1152)

## What the Model Reads Got Smaller and Truer

A forensic audit of live production prompts (#1160) found an interactive turn shipping ~33k tokens of system prompt, over a third of it redundant. The findings landed as a series:

- **History ships once.** The system prompt no longer carries a second JSON transcript of conversation history the model already receives as role-native messages — the largest single duplication found, and a permanent prompt-cache breaker. The session catalog that remains is curated: empty rotation sessions filtered, capped, with truncation always explicit. (#1164)
- **Time reads at a glance.** Context deltas are now tiered — exact seconds under an hour, `-26h45m`, `-5d9h` beyond — so ambient recency never depends on the model doing division mid-task. Every tool that accepts a timestamp round-trips the same compound forms. (#1165)
- **Provider drift cleaned up.** Deictic framing rewritten from the model's vantage point, missing section headings added, and the channel overview made deterministically ordered so prompt bytes stop churning turn over turn. (#1166)
- **Structural debt from the v0.10.0 audit retired.** All thirteen deferred findings resolved, plus this release's own pre-release audit fixes (field-level Godoc across the new checkout/provenance surfaces, one model-facing field naming consistency fix). (#1131, #1174)

## Conversations Hold Together

Two production incidents this cycle traced to the same report — "thane can't hold a coherent conversation" — and both root causes are fixed.

- **Compaction no longer corrupts what it protects.** Four compounding defects fixed: concurrent compactions raced during the slow summarize call and stacked triplicate summaries; summaries were immortal and re-armed the trigger forever; summaries landed mid-dialogue at wall-clock time instead of at the region they replaced; and the cutoff split turn pairs, orphaning replies. Compaction is now single-flight, folds prior summaries into exactly one correctly-positioned summary row, and marks precisely the messages it summarized. The budget is finally config-driven (`compaction.max_tokens`, default 32000 — the old hardcoded 8000 compacted interactive conversations absurdly early). Already-polluted conversations self-repair on their next compaction. (#1170, #1168)
- **A runaway shell command can't wedge a turn.** The `exec` tool's timeout used to kill only the direct `sh` child; an orphaned grandchild holding the output pipes blocked the turn for its whole lifetime — in the triggering incident, a `find /` held a Signal conversation hostage indefinitely. The command now runs in its own process group killed as a unit at the deadline, with a `WaitDelay` backstop for anything that escapes the group. (#1169, #1167)

## Deprecation Becomes a Scheduled Obligation

The legacy WebSocket aliases (`/v1/companion/ws`, `/v1/platform/ws`) had no deprecation signal, no usage telemetry, and no sunset date — the shape of a shim that lives forever. A single legacy-route registry now drives the alias routes, the OpenAPI coverage allowlist, RFC 8594/9745 `Sunset`/`Deprecation` headers on the upgrade, an in-band `deprecation` notice in `auth_ok`, per-connection usage telemetry, and a CI gate that fails once the removal window passes. Culling becomes a one-line registry edit backed by data. The pattern is path-type-agnostic for every future alias. (#1172, #1084)

## Upgrade Notes

1. **`thane_curate` and `thane_create_container` are removed**, consolidated into `thane_loop_create`. Live loop definitions are unaffected (verified against production); anything scripted against the old tool names must move to the new front door. (#1129)
2. **The legacy WebSocket aliases are formally deprecated** with a sunset of **2026-12-25**. Clients on `/v1/companion/ws` or `/v1/platform/ws` should migrate to `/v1/realtime/ws`; until then they'll see `Sunset`/`Deprecation` headers and a `deprecation` object in `auth_ok`, and each connection logs a warning server-side. (#1172)
3. **New config: `compaction.max_tokens`** (default 32000) replaces a hardcoded 8000-token compaction budget. No action required; operators who want the old aggressive compaction can set it explicitly. Conversations polluted by the old compactor heal on their next compaction pass. (#1170)
4. **Context deltas changed shape** above one hour (`-26h45m`, `-5d9h` instead of raw seconds). Anything parsing thane's model-facing delta strings externally should use the same tiered grammar; all built-in tools accept both old and new forms as input. (#1165)
5. **`doc_at` output renamed `as_of` → `timestamp`** for consistency with `doc_history`/`doc_diff`. (#1174)
6. **Optional new config for co-authored roots**: `git.remote` on a document root enables fast-forward-only sync, and operator `allowed_signers` gates whose commits verify. Both are opt-in; roots without them behave exactly as before. (#1143, #1138)

## Known Limits

- The remote-sync engine is in its first release. It is deliberately conservative — fast-forward only, fail-closed on divergence or rewind, no force-push path exists — so the failure mode is "sync pauses and tells you why," never silent history loss. Expect to resolve divergence on the workstation.
- Worker loops still run with the full identity prompt; the trim mechanism exists and the rollout decision is made, but per-loop adoption is deferred to a future release (#1171).
