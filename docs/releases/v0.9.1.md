# v0.9.1 - The Operational Hardening Release

> **Note:** v0.9.0 was published under the tag `v0.9.0-rc` because of a release tooling mistake. This release compares against `v0.9.0-rc`, which is the real v0.9.0 release.

v0.9.1 is the first release after the convergence work of v0.9.0. The architecture is no longer trying to become one thing; now it starts getting sharper, safer, and easier to operate as that one thing.

The theme is production hardening. Managed documents become a real knowledge substrate instead of a thin file wrapper. Runtime logs become structured forensic datasets instead of one noisy stream. Capability tags and tool registration stop depending on startup timing. Scoped Home Assistant watchlists become loop-owned context lanes with compact history summaries. Anthropic prompt caching gets the accounting, retry behavior, and guardrails it needed for daily use. macOS releases move closer to the way Thane is actually run in production.

**183 files changed, 18,265 insertions, 2,577 deletions.**

## Operational Backbone

**Structured log datasets.** The old monolithic `thane.log` shape gives way to category-partitioned JSONL datasets under `logging.root`. Requests, loops, delegates, envelopes, access records, and runtime events now have stable record envelopes and their own storage lanes. Stdout becomes a quieter operator surface instead of a catch-all forensic sink. This gives future retention and tiering work clean boundaries while making live debugging less noisy. (#698, #734)

**Message envelopes.** Loop-to-loop notification starts moving onto a shared message substrate. The new envelope bus introduces sender and destination identity, validation, routing, and audit records, with live timer-driven loops as the first real delivery backend. `notify_loop` becomes a thin model-facing wrapper over that bus instead of another bespoke wake path. (#696, #717)

**Runtime diagnostics.** `logs_query` gets clearer model-facing semantics. The `pattern` parameter is now explicitly message-text search, while loop IDs, request IDs, tools, models, sessions, conversations, and subsystems have named filters. Empty pattern-only searches now return a recovery hint when an attribute filter probably matches the user's intent. (#730, #732)

## Document Substrate

**Managed document roots.** Thane now has an indexed document provider over managed markdown roots such as `kb:` and `scratchpad:`. The model can browse, search, outline, inspect sections, and discover frontmatter values without brute-force file walking. The `documents` capability becomes a real corpus-navigation surface. (#705)

**Document-native editing.** Common managed-root mutations stay in document space instead of falling back to raw filesystem paths. `doc_read`, `doc_write`, `doc_edit`, rolling journal updates, delete, move, copy, and section transfer operations all preserve semantic refs like `kb:README.md`. This directly fixes the class of failures where delegates discovered a document semantically and then wrote to the wrong path shape. (#706, #707, #708)

**Reference-quality navigation.** The remaining indexed-navigation gap closes with link traversal, backlinks, canonical refs, bounded graph output, structured frontmatter filters, frontmatter key presence, and modified-time search. The document index can now answer questions like what points at this article, which docs were updated recently, and which notes carry a particular status or area. (#628, #722)

## Scoped Awareness

**Tag-owned watchlists.** Watched Home Assistant entities move from a single global list to scoped subscriptions keyed by tag and entity. Orchestrator can create a task-specific loop tag, subscribe entities against that tag, and give the loop a curated context lane without adding a second ownership model to loop definitions. Existing unscoped rows migrate automatically. (#669)

**History-aware context.** The existing `history` hint now does real work. Numeric entities get compact trend, min, max, and delta summaries; discrete entities get transition summaries. The design stays intentionally conservative: enough context for a loop to notice meaningful movement, not a general analytics subsystem. (#669)

## Tool and Context Assembly

**Deterministic tool registration.** The tool suite now assembles before capability tags are finalized. `tools.Provider` gives subsystems a common declaration contract, while async runtimes such as Signal can declare tools early and bind handlers later. This fixes the `add_context_entity` missing-from-`awareness` bug and removes a whole class of startup-order drift. (#733, #746)

**Cleaner default surfaces.** Fresh core conversations no longer leak platform, notification, and loop-control tools through `AlwaysAvailable`. Core starts smaller and capability activation owns the broader surface. (#725)

**Prompt-formatting primitives.** Context providers move closer to their domain owners, and shared model-facing formatting helpers consolidate into `internal/promptfmt`. The awareness package keeps the responsibilities it actually owns: current conditions, context usage, entity formatting, and watchlists. (#625, #745)

## Loop Authoring

**Live loop control.** The loop runtime grows model-facing tools for inspection, ad hoc spawning, and clean stopping. Temporary background loops can now behave more like delegates: do work in the background, use ordinary tools for durable artifacts, and report back through normal completion paths. (#710)

**Service-loop guardrails.** Loop authoring gets safer. Native `set_next_sleep` becomes the canonical adaptive sleep-control path for timer-driven service loops, and `loop_definition_lint` catches common definition mistakes before they become noisy runtime behavior. Natural-language timing in a task is no longer treated as enough; the model gets explicit warnings when cadence fields are missing or delegation gating does not fit the intended service shape. (#719, #720, #721)

**Launch schemas.** `loop_definition_launch` and `spawn_loop` now expose the real launch override fields directly instead of hiding them behind an opaque object. Misplaced `metadata.model` overrides fail loudly instead of silently routing to the default model and inviting the agent to narrate a result it did not actually run. (#729, #731)

## Anthropic Provider Hardening

**Schema compatibility.** Anthropic tool schemas are sanitized at the provider boundary, and bridged MCP schemas are sanitized at registration time with operator-visible logs. Top-level composition keywords no longer cause 400s during tool-heavy requests. (#723, #724)

**Caching reliability.** Anthropic 429 and transient 5xx responses now retry with backoff and `Retry-After` support. Cache breakpoints are capped and checked against model-specific minimum prefix lengths so unsupported cache attempts become visible instead of silently ineffective. (#741, #739, #747)

**Caching accounting.** One-hour cache writes now use the correct 2.0x input multiplier instead of the 5-minute 1.25x rate. Usage records preserve the 5-minute and 1-hour buckets separately, and cache hit rate is surfaced in logs and session snapshots so operators can tell whether caching is actually paying off. (#736, #737, #747)

**Caching documentation.** New caching docs explain section TTL policy, model minimums, validation signals, and common anti-patterns. The docs are cross-linked from model-facing context guidance so future prompt-section changes have a place to check the caching contract. (#743, #748)

## macOS Operations

**Installer packages.** macOS release artifacts move from notarized zip payloads toward signed, stapled `.pkg` installer products. The package aligns with Thane's home-scoped install model, installs into `~/Thane/bin`, and gives Apple tooling an artifact that can carry the full notarization ticket. (#709, #718)

**Release and deploy workflow.** Release engineering moves into readable helper scripts and `just` recipes for building macOS packages, publishing guarded GitHub releases, and deploying pkg artifacts to live hosts with remote signature inspection and version verification. (#692, #700-#704, #718)

**Production Mac guidance.** macOS operators are pointed at the companion `thane-agent-macos` app as the native, integrated way to run Thane on a Mac. Package payload filtering also now strips AppleDouble and related filesystem artifacts before release. (#750, #752)

## Documentation and Maintenance

- Tool reference documentation now reflects the actual catalog and capability tags rather than the older pre-0.9 surface. (#748)
- Managed document, release engineering, Anthropic caching, and model-facing context docs are updated for the current runtime shape. (#722, #747, #748)
- SQLite, Go networking, sqlite3, and GitHub Actions dependencies are refreshed. (#711-#716, #726, #727, #749)

## Upgrade Notes

If upgrading from v0.9.0 (`v0.9.0-rc`):

1. Expect log files to appear in structured dataset directories under `logging.root` rather than only in the old monolithic shape.
2. Existing watched entities migrate into the normalized watchlist subscription table automatically.
3. Existing Anthropic usage records remain valid; new records split 5-minute and 1-hour cache creation tokens for correct cost accounting.
4. macOS operators should prefer the packaged release/deploy workflow and the companion `thane-agent-macos` app for production hosts.
