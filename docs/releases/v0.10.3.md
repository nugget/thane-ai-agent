# v0.10.3 — The Trust Boundary Release

v0.10.2 was about the home. v0.10.3 is about the instance itself: everything that defines a running Thane — its configuration, the talent documents that steer the model each turn, and the definitions of its built-in service loops — now lives in `core`, a signed git repository that is verified before the agent will start. Trust is declared per root rather than globally, each root naming the keys entitled to found it. A new `self` root separates what Thane writes about itself from what constrains it, with every revision attributed to the model, loop, and request that produced it. Around that spine, three arcs open and close within the release: loop output gains a structured publishing contract (facets) *and* the consumers that make it real, the metacognitive loop is re-scoped from household watching to internal operations and ends the cycle publishing a one-line system self-assessment into every conversation, and Home Assistant support tracks the 2026.8 device-registry split.

## Config Is Verified Before It Is Obeyed

Config decides what gets verified — which keys sign, which models run, which document corpora may reach the system prompt — yet it was the one input nothing verified, discoverable in six filesystem locations, first match wins. Controlling config meant never needing to defeat signature verification at all. (#787)

- **Config loads from exactly one place: `<workspace>/core/config.yaml`**, covered by the root's signed history. The search path is gone; the workspace comes from `-workspace`; `workspace.path` in config is rejected at load since the config's location now states it. (#1257, #1263)
- **`thane serve` refuses to start on a core it cannot verify.** `thane validate` gains an integrity report — repository present, history verifies, key material untracked, config committed, tree clean — printing each failing check with the command that fixes it, and the boot gate consumes the same checks so the two cannot drift. Terminal failures exit 78 so supervisors stop retrying. (#1258, #1260)
- **The escape hatch is explicit and degraded.** `-config` is rejected; its replacement is named `-insecure-config`, and running under it enters safe mode: tools that message humans directly are refused at the registry with an error explaining why, service loops do not auto-start, `/health` reports `trust: unverified`, and the model is told up front. (#1259, #1261)
- **A corpus reaches the prompt because policy says so.** Document roots gain a declared `context:` policy (`inject`, `search`, `requires_tag`); injection eligibility is no longer inferred from document tags, which mattered once roots began syncing from remotes — tag-inferred injection would have let anyone with push access place text in the system prompt. (#1255, #1262)

## Each Root Founds Its Own Trust

A single global `signing.allowed_signers` list flattened different trust domains into the widest one: adding a collaborator to a shared knowledge corpus also made them a valid signer for the root holding the config — a live escalation path found in a configuration headed for deployment. (#1264)

- **Per-root `seed_signers` replace the global list.** Each signing root declares the permanent keys entitled to found it and widen its trust file. `.allowed_signers` is written once at creation and never reconciled from config again, and the declared seeds remain a floor during verification, so a corrupted trust file cannot lock out the operator entitled to repair it. (#1266, #1271)
- **A root proves its birth before its history counts.** Admission requires the parentless first commit — and every commit that ever touched `.allowed_signers` — to be signed by a declared seed, judged against a seed-only rendering so a commit cannot be validated by the key it introduces. The check is order-independent (roughly two signature verifications even on a 4,000-commit root) and runs for every git-backed root. (#1267)
- **Verification can no longer be reassigned by the repository being verified.** A confirmed bypass: `gpg.ssh.program` is settable in a repo's own `.git/config`, and a substituted program can produce a "Good" verdict for an attacker key. All verification seams now pin `gpg.format=ssh` and a resolved `ssh-keygen` on the command line, with a regression test that fails without the fix. (#1270)
- **`thane init` records who founded the instance**, defaulting the operator seed from git's own `user.signingkey`, with `-operator-key` to override. Without a signable key, core is founded self-signed — admissible and clearly labeled, never a silent fallback. Rounding out the arc: admission's git invocations are argument-safe (a file literally named `HEAD` in a root no longer refuses boot), and the verification test suite went hermetic against developer git config. (#1272, #1326, #1269)

## Talents Move Inside the Boundary

Talents shape model behavior on every turn, and they lived outside every boundary this project has built — production's talent directory was not even a git repository. (#1278)

- **Talents now load from `core/talents`, full stop.** A configured `talents_dir` is rejected at load with migration instructions. `thane init` places the bundled set in core's birth commit, so a fresh instance never has unsigned behavior definitions; from now on a talent edit is a signed commit, and an uncommitted talent fails boot the same way an uncommitted config does. `just init` delegates to `thane init`, and an instance that boots with an empty talent set now says so loudly instead of quietly running unguided. (#1279, #1352)
- **When a talent applies is declared, not guessed.** Two applicability tags — `always` (every turn) and `persona` (only where the persona renders) — replace "no tags means always-on." A file with frontmatter but no tags is a boot error naming the file; a file with no frontmatter is skipped as an ordinary document, retiring the filename-capitalization heuristic that had been the only thing keeping `README.md` out of the prompt. Six foundation talents moved to `persona`, trimming identity prose from task-mode turns. Roots can also declare an untagged-document policy outright (`context.untagged`), and a sweep for claims the tags had just broken found one stale promise and fixed it. (#1283, #1285, #1280, #1286)

## The Self Root

Core is meant to carry an operator-anchored identity claim, and it can't while agent loops rewrite it every fifteen minutes — in production, 97 of the 100 commits after the operator-signed birth were the agent's. The dividing line is what constrains Thane versus what Thane produces: axioms, persona, talents, and loop definitions stay in core (a loop that could edit its own definition could remove its own egress restrictions), while agent-authored self-knowledge moves to a derived `self` root held to the same integrity standard. (#1318)

- **The reflective loops write to `self`.** `ego.md`, `metacognitive.md`, and `archivist.md` move there; a test pins the pairing (constraints resolve under core, self-knowledge under self) so a loop can never write one root while the prompt reads another. A missing core or self is a validate failure naming the recovery, not a silent omission. (#1321, #1323, #1324)
- **Every revision says which mind wrote it.** Git-backed root writes now stamp signed commit trailers — model, loop, conversation, request, tool call, and the core commit that was active when the words were written — and `doc_history`/`doc_at` surface them as structured attribution. Reconstructing five months of production history without this had topped out at 89.7% attribution. When the committed content carries facets, the status line becomes the commit subject and the digest the body, so `git log --oneline` on a state document reads as a timeline of verdicts. (#1322, #1366)
- **Identity is inspectable as evidence, not a self-issued verdict.** `GET /v1/identity` reads the founding key material from the birth commit's tree and reports the instance ID, key fingerprints, anchor posture (`operator` / `self_signed` / `unknown`), and admission status — deliberately with no `trusted: true` for an instance to award itself. (#1319, #1316)

## Core Loops Are Documents Now

The three built-in loops — ego, metacognitive, archivist — were the last loops defined in Go rather than data. They are now markdown definition documents (frontmatter, a fenced yaml spec, prompt prose as sections) shipped with the binary and overridable from `<core>/loops/`; by the end of the cycle the Go definitions were deleted outright, so editing a core loop's mandate is a document edit, not a build. (#1086, #1308, #1310, #1311, #1347, #1349)

- **A definition that won't parse fails at `thane validate`**, which now reports each document's loop, graph placement, and generated output tools; at boot a malformed definition exits 78 instead of crash-looping under a supervisor. Graph placement itself lives in the documents, and a new reference (`docs/reference/loop-definitions.md`) documents every authorable spec key, gated by a reflection test so a new field cannot ship undocumented. (#1315, #1317, #1360)
- **And as of this release, the shipped documents actually load.** The boot path read the core root's location before wiring populated it — silently falling back to embedded defaults for as long as legacy `enabled:` config flags kept seeding byte-identical copies, and silently dropping the three loops entirely once those flags left the config. Boot now resolves the path the way `thane validate` always has, and logs the directory and document count so the substitution can never be invisible again. The archivist's last config gate went with it: the definition document is now its single switch, so removing the dead `archivist:` config section can no longer leave the session-close queue producing into a void. (#1367, #1361)
- **A worker loop can shed the identity it never used.** Mechanical loops carried the full ~35KB reflective stack — axioms, ego, persona talents — on every wake of a job like "fetch a webpage and update a document," the largest latency lever the #1160 audit found for local-model turns. `prompt_mode` is now a durable spec field (`task` sheds the identity stack; `full` is the default), hot-swappable into running loops without a relaunch, with the three reflective core loops pinned `full` in their documents so no future default can lobotomize them. A pre-rollout audit caught that task mode also dropped the loop's own subscriptions and self-view — a watcher would have woken blind — so loop-scoped context now survives the trim. (#1171, #1358, #1364)
- **The metacognitive default cadence was corrected** from 2m–30m sleep to 15m–60m — deleting a redundant config block would otherwise have quintupled the wake rate — and all documented copies of the defaults are now test-gated against the applied values. A loop can also see its sleep envelope before choosing: bounds ride the loop's own status view and the per-loop `set_next_sleep` description, alongside lived rhythm (planned versus actual sleep, early wakes, wake counts). (#1312, #1313, #1314)
- **Ego verifies before it claims.** Production ego on a local model treated its own last entry as evidence and propagated a phantom subsystem for a week. Its mandate now opens with a grounding gate (prior entries are claims to verify, not facts to build on), its supervisor pass hunts echo and propagated fabrication with authority to prune, and its profile routes every wake to a frontier-class model. The prompt audit that came with the document move also fixed a data-loss hazard: the loop now reads its document before rewriting it, instead of reconstructing it from a truncatable context block. (#1362, #1349)

## Faceted Loop Output

Service loops maintain documents that several consumers read at very different sizes — a wall display wants one line, a colleague wants a paragraph, the operator wants everything. The convention existed as hand-authored markdown sections and failed the way hand conventions do: nothing enforced sizes and no consumer could ask for a level. The contract is now structural — declared **facets** (`status_line`, `teaser`, `digest`; `full` is the document body), an `audience` axis, and private `working_notes` — and by the end of the release, every read surface consumes it. (#1250)

- **One publish carries every projection.** A generated per-loop `publish_output_*` tool takes all declared facets plus the full body in a single call, so a status line never describes a state the details have moved past. Size budgets reject with a corrective error rather than truncating — and after production's first over-budget publish, the teaching everywhere says what the validator means: a ceiling to compose comfortably under, not a target to graze. The model writes content, never headings; the framework owns document structure. (#1251, #1254, #1368)
- **Facets are projections, not truncations.** The original name `tiers` implied each level was the one above it shortened — exactly the authoring mistake to avoid — so the vocabulary changed. A facet can declare a format (`json` is enforced, and survives round-trip as data). (#1300, #1301, #1304)
- **Every reader now speaks the contract.** `doc_read` takes a `level`, so a consumer states the cost it can afford and gets what the author wrote for that size. `doc_search` returns the authored teaser as the snippet (status_line as fallback, derived paragraph only for unfaceted documents) and advertises each hit's facets so the follow-up is one targeted read. LoopView carries a loop's declared outputs end to end, and `GET /v1/loops/{name}/outputs/{output}` negotiates fidelity on `Accept` — `text/plain` returns the status line alone, `application/json` the typed fields. And the loop's own context stopped being the last blind reader: instead of byte-truncating the rendered document at 16KB, a faceted document now rides in as its authored projections plus the full body, mirroring the publish tool's shape so a republish is mechanical. (#1307, #1371, #1372, #1370)
- **Private things stay private.** `working_notes` carry `audience: internal`, and `doc_search` excludes internal documents by default (with explicit opt-ins). Notes are a maintained document the loop rewrites — current thinking, not an append-only log it must re-read past. (#1252, #1298)
- **New loops start with correct cues.** `thane_loop_create` scaffolds a declared output as the exact shape the publish tool writes (working notes created and marked internal from birth), accepts an optional `output.initial` first publish authored by the creating model — which knows things the loop's smaller model would never rediscover — and grants any output-declaring loop the read-side document tools regardless of its capability tags. (#1327, #1328, #1330)
- **Legacy doors closed, and the substrate stopped fighting back.** The `journal_document` output type and its append tools are retired; the metacognitive loop's runtime iteration-log writer is deleted (its unwired provenance store had been quietly dirtying core every iteration until the new boot gate refused to start — the document's git history *is* the iteration log); and the never-used `fallback_content` spec field is gone. `doc_edit` repairs the doubled-heading pattern that had been accreting in maintained documents, and the write chokepoint now folds tokenizer typography impostors — the U+202F narrow spaces and U+2011 hyphens that local models emit — so alternating authors stop churning invisible diff lines through signed history. (#1299, #1277, #1297, #1249, #1357, #1369)

## Loop Lifecycle: Creation Guided, Removal Honest

Tool-usage data settled a debate: across 31,594 archived calls, the simplified creation tool was out-used two-to-one by the full-spec tool it wraps, because a flat wrapper offers nothing in exchange for its limits. And a production incident showed removal was worse than limited — an agent "removed" a loop by deleting its output document and reporting success while the live instance ran on. (#1287, #1333)

- **The `loops` capability gained a trailhead** — the decision map that was buried in 340 lines of flat doctrine: whether the job is a loop at all, stored versus ephemeral, and the traps between the two. (#1288)
- **`thane_loop_create` gained `dry_run`** (plan without writing; the result round-trips through the same decoder the expert tool uses, so the two doors compose) **and output fluency** — declared facets now actually generate the publish tool, unknown facet names are refused rather than dropped, and document-owning loops automatically get a working-notes output. A reflective test now forces every spec field to be either offered in the creation schema or allowlisted with a written reason. (#1294, #1295, #1296)
- **Removal reports what actually happened.** `loop_definition_delete` verifies the live layer and says so — running loop stopped, none running, or still live with recovery steps — and lists the output documents it deliberately leaves in place. `stop_loop` on an active durable definition now warns that the reconciler will relaunch it. (#1333)

## The Metacognitive Loop Turns Inward

The metacognitive loop's original mandate — watch the household — predates the purpose-built loops that now do that job better. Meanwhile the system's internal health signals (connection watcher, memory guard, event-bus drops, queue depths) were computed but consumed by nothing, and wake causality wasn't recorded at all. The loop is re-scoped to internal operations: Thane thinking about Thane. The arc is deliberately observe-only — every new tool is read-only, and escalation to the core loop remains the only egress. (#1341)

- **Wakes carry attribution.** Every loop wake records why and from where, with a deterministic precedence, surfaced on loop status and in events; a persistent lifecycle journal keeps them across restarts, and queue consumers journal completions. Production's first week then taught two honesty lessons: the wake census now reports the window it actually covers instead of letting eight minutes of post-restart data wear a 24-hour name (the confabulation seed behind metacog's first bad theory), and the boot record survives startup write contention on a busy log database instead of silently losing the deploy story. (#1342, #1344, #1343, #1355, #1353)
- **One health snapshot, many consumers.** A new inspector assembles connection lamps, memory-guard state, bus and log-index loss, doc-root sync, queue backlog aging, and a per-root document-churn detector into a single snapshot — served as the zero-argument `system_health` tool, injected into the metacognitive loop's context each iteration, and now carrying an ambient tally of the system's own WARN/ERROR stream (since-boot counters, a rolling hour, newest samples with attribution) so the loop notices trouble without being asked to go query for it. Three more read-only tools (`queue_status`, `doc_activity`, `loop_activity`) join it under a new `diagnostics` capability tag. (#1345, #1346, #1354)
- **The mandate was rewritten** around perceive → investigate → judge → escalate, removing two capabilities the old prompt promised but never granted, and deploys are perceivable: each process start journals its version and commit, and the health snapshot precomputes the deploy story — running versus previous version, jump class, boot counts — leaving the verdict to the loop that reads it. (#1348, #1350)
- **The verdict now reaches the operator's conversation.** Metacog's state document declares `status_line` and `digest` facets, its write tool became the faceted publish, and a new always-on provider injects the one-line system self-assessment — with its age — into interactive context each turn. `system_health` is the annunciator of facts; this is the annunciator of judgments ("panel clean, baselines steady" versus "two concerns open"), and it is the first consumer of the facet contract outside the document layer. (#1351, #1365)

## Home Assistant 2026.8

HA 2026.8 splits multi-integration devices into one registry entry per integration; on the reference install, 101 of 1,075 device names became ambiguous overnight, and both of Thane's name-based resolvers were first-match-wins — a coin flip between a controllable device and its presence-tracker shadow. (#1337)

- **Ambiguity is surfaced, not guessed away.** `ha_device` returns structured candidates (integration, entity count) on an exact-name tie; `ha_call_service` device targets match user-assigned names and fail fast on multi-match. The registry model adopts 2026.8's config-entry ownership with a fallback for older servers. (#1338)
- **Thane's own MQTT devices moved to modern device-based discovery** — one retained config per device instead of ~73 per-sensor messages — performing HA's documented three-step migration itself so entity IDs, customizations, and history survive an unattended deploy. (#1340)
- **Area subscriptions respect the operator's Visible boundary**: expanding an `area:` target now applies the same salience filter as area snapshots (disabled always out; hidden and diagnostic entities excluded unless asked for), so watching a room no longer means watching everything its owner deliberately hid. (#1329)

## Operational Hardening

- **Local-model routing now believes its own health checks.** During a July network outage, the health watcher marked the local ollama runner down within a minute while routing sent it 306 doomed requests in an hour. Router scoring now consults live readiness (a confirmed-down resource is penalized below every alternative), cooldowns trigger on connection-class failures rather than only timeouts, and the session summarizer reports outcomes so its failures also fail over. (#1335)
- **The inbound Ollama-compatible listener is hardened**: optional bearer-token auth (`ollama_api.api_key`), request bodies capped at 32 MiB, all inbound system messages stripped rather than just the first, streaming errors sanitized through the same client-safe mapping as non-streaming, and `/api/version` reporting the real build. (#1336)
- **Companion tool collisions distinguish normal from wrong.** Two Macs advertising the same tool is the supported deployment, but ties broke on a per-connection random ID — re-rolling the winning schema every reconnect and letting the model read one machine's contract while dispatching against the other's. Ties now break on configured identity, and only genuine schema divergence warns. (#1284)
- **The log archiver stopped starving the live writer.** The nightly archive's per-ID deletes held SQLite's single WAL writer long enough to starve the live logging path into `SQLITE_BUSY`; deletion is now one `IN`-list statement per table, and the placeholder idioms it exposed were consolidated into shared helpers. (#1289, #1290)
- **Production WARN/ERROR is one command away.** `just alerts` follows new structured log records from the SQLite index; the pipeline reports its own failures (backpressure, write errors, dropped subscribers) instead of silently thinning; and an agent run that exhausts its iterations surfaces as a warning with its finish reason — the exact silence that let the email handler fail politely for weeks. (#1309)
- **The release record lives in the repository**: all published release bodies are archived under `docs/releases/` with an index and a provenance manifest, and the committed markdown file is now the source for every future release body — this document included. The release checklist also gained a toolchain-and-recipe audit, born from a CI collapse traced to a linter pinned across three upstream releases while a retry loop hid its known race. (#1305, #1359)
- **Housekeeping.** golang.org/x/net 0.57, actions/setup-go 7, goldmark 1.8.5, modernc.org/sqlite 1.55, plus README and doc-table cleanups. (#1242, #1244, #1245, #1331, #1247, #1332, #1246, #1241)

## Upgrade Notes

This upgrade rearranges where things live; prepare the workspace before deploying the binary, and run `thane validate` first — every failing check prints its fix.

1. **Move config into `<workspace>/core/config.yaml`, covered by a signed commit.** The six-location search is gone; `-config` is rejected (its successor `-insecure-config` enters degraded safe mode — egress tools refused, service loops parked); `workspace.path` in config is rejected at load. `thane serve` refuses to boot (exit 78) on a core that fails the integrity report. (#1257, #1259, #1260, #1261, #1263)
2. **Replace `signing.allowed_signers` with per-root `seed_signers`.** Every signing root needs its seeds declared, and admission now judges every git-backed root's birth. Agent-founded roots fail admission until the agent's principal and public key are added to their `seed_signers` — a config change, no history rewrite. (#1266, #1267)
3. **Talents load from `core/talents` in the signed root; `talents_dir` is a rejected config key.** An uncommitted talent fails boot like an uncommitted config. Every talent must declare `tags:` (`always` or `persona`) — and the dangerous direction is silent: pre-tag foundation files carry no frontmatter and would be skipped as ordinary documents, dropping identity prose from every prompt. Back-port the tagged talent files as signed commits *before* deploying, then confirm the boot log shows the expected talent count and no unexpected skip notices. (#1279, #1283, #1285, #1352)
4. **The reflective loops now write to the `self` root.** `ego.md`, `metacognitive.md`, and `archivist.md` live at `self:`, with deliberately no automatic migration — move the existing documents into `{workspace}/self` by hand or the loops start from empty pages. `thane validate` fails on a missing core or self, naming both recoveries. (#1321, #1323, #1324)
5. **Core loop definitions boot from shipped documents — and this release is the first where that path actually loads.** Adopt the current documents wholesale in your next `core/loops` backport (they carry `intent`, `parent_name`, `prompt_mode: full` pins, and reference pointers), check for stale overrides that would pin an old mandate, and do **not** re-add legacy `ego:`/`metacognitive:`/`archivist:` `enabled:` stubs — the documents are the switch now. Verify the boot log's core-loops line reports the expected directory and document count. The `archivist:` config section is dead after the new binary runs; remove it then, not before. Installs relying on defaults get the corrected metacognitive cadence (15m–60m). (#1367, #1361, #1312, #1360)
6. **The metacognitive pivot rebuilds its own state, and ego costs more per wake by design.** Metacog's `self:` document reorganizes around internal-ops baselines on its first faceted publish; new journal tables auto-create on both databases. Ego's profile now routes every wake to a frontier-class model (`quality_floor: 8`, `local_only: false`) — a deliberate spend increase for the loop whose failure mode was confabulating its own history. (#1341, #1365, #1362)
7. **Roll `prompt_mode: task` onto mechanical worker loops** — one `loop_definition_update` per loop, no relaunch needed. Reflective loops stay `full` (the shipped three are pinned). Workers keep their subscriptions and self-view under task mode. (#1358, #1364, #1171)
8. **Removed:** the `journal_document` output type and append tools (stored specs are warned and skipped — repair deliberately, since converting to `working_notes` changes the audience), and the unused `fallback_content` spec field. **Changed:** `doc_search` excludes `audience: internal` by default; `set_next_sleep` returns a `sleep_envelope` object instead of flat keys. (#1299, #1297, #1252, #1314)
9. **Relaunch persisted `email-default-handler` definitions** — the delegation-gating fix is not a live-retune scalar. (#1309)
10. **After deploy, verify the MQTT device-discovery migration ran** (phases logged; entity IDs should survive). Expect same-name device twins in HA 2026.8 — pick by integration. (#1340, #1338)
11. **`ollama_api.api_key` exists but leave it unset if Home Assistant talks to the endpoint directly** — HA's Ollama integration cannot send tokens. (#1336)

## Known Limits

- **Safe mode restricts messaging, not actuation** — device control, shell, and web tools remain available under `-insecure-config`, and a failed verification has no posture outside `serve`. Cataloged in #1268; unshipped.
- **Verification is HEAD-scoped** (no per-file revocation, #1136), core's own admission runs only under `verify_signatures: required` (#1276), and a substituted git binary is out of scope pending native signature verification (#1270).
- **Facets stop at the document boundary.** Every in-process reader speaks the contract now, but the outward motion — Home Assistant entity bindings, MQTT emissions, watch complications, and facet-change wakes — is deliberately deferred to #1356 with the design findings recorded there.
- **The talent loader still exists.** Talents live inside the trust boundary, but collapsing the dedicated loader into ordinary tagged-root injection (and the vocabulary rename that follows) moved to #1373. The guided creator's inference-first mode likewise remains unbuilt (#1287).
- **Ollama outbound-client fixes are not in this release** (missing `num_ctx`/`keep_alive`, the stream-killing timeout, swallowed stream errors); #1334 remains open.
- **The internal-ops arc is observe-only by design** — it diagnoses; remediation still routes through the operator and the core loop.
