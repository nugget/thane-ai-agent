# v0.8.2 — OpenClaw Compatibility Profile

OpenClaw workspace-aware agent behavior, exposed as a faux Ollama model on Thane's existing API. Plus logging field fixes that complete the structured logging work from v0.8.1.

**22 files changed, 1,608 insertions, 79 deletions across 7 commits.**

## Highlights

### thane:openclaw Faux Ollama Model (#256, #528)
- New `internal/openclaw` package exposes a `thane:openclaw` model on the Ollama-compatible API (port 11434) that replicates OpenClaw v2026.2.9 workspace-aware agent behavior using Thane's existing agent loop
- Loads workspace files (AGENTS.md, SOUL.md, USER.md, MEMORY.md, etc.) in OpenClaw's canonical injection order with subagent filtering
- Skill discovery from SKILL.md files, assembled into `<available_skills>` XML blocks
- System prompt assembly follows OC conventions: identity, skills, memory recall, project context, heartbeat instructions
- File truncation using OC's 70/20 head/tail strategy at 20K chars
- Pre-compaction memory flush when tokens approach threshold
- Agent loop extended with `Request.SystemPrompt` field — profiles can override default prompt assembly without duplicating the loop
- Configurable via `openclaw:` section in config.yaml (workspace path, skills dirs, max file chars)

### Daily Memory Injection (#531, #532)
- `LoadWorkspaceFiles` now automatically includes today's and yesterday's `memory/YYYY-MM-DD.md` files after MEMORY.md
- Gives thane:openclaw awareness of recent work without requiring file tool calls
- Matches Docker OpenClaw's automatic daily file injection behavior
- Silently skips missing files; excluded in subagent mode; respects maxChars truncation

## Bug Fixes

- **Structured log field mismatch** (#529): Agent loop used `session` and `conversation` field names but the SQLite indexer expected `session_id` and `conversation_id` — all agent loop logs were silently unindexed, breaking the web UI log viewer's session/conversation filtering. Renamed fields throughout agent loop, memory/compaction, archive_adapter, and tools/tempfiles.
- **Truncated session ID in log context** (#529): `session_id` was populated with the ShortID-truncated value, preventing the indexer from matching full session IDs. Full session ID now used in log context; short form kept only for usage records.
- **Context logger propagation** (#529): Metacognitive loop and tool handlers used the base logger instead of `logging.Logger(ctx)`, so supervisor flag, subsystem, and conversation_id weren't propagating. Switched to context loggers throughout.
