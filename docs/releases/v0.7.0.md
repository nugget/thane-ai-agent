Phase 3: Autonomy. Thane can now read and reply to email, manage its own capabilities, and route decisions based on who's asking.

**111 files changed, 21,603 insertions, 842 deletions across 147 commits.**

## Highlights

### Native Email (IMAP + SMTP)
- Full IMAP client: `email_list`, `email_read`, `email_search`, `email_folders`, `email_mark`, `email_move`
- SMTP send/reply with markdown-to-HTML conversion: `email_send`, `email_reply`
- Automatic email polling with UID high-water mark tracking
- Wake prompt with triage instructions — agent reads, decides, replies, archives
- Trust-zone-gated sending: owner/trusted send freely, known requires confirmation
- Auto-Bcc owner on all outbound email for audit trail
- MIME charset handling for ISO-8859-1, Windows-1252, and other legacy encodings
- Messages marked as read (`\Seen`) on read — because reading means read

### Capability Tag System
- Tag-driven tool and talent loading: `[email]`, `[ha]`, `[calendar]`, etc.
- Tags declared in config, activated per-session
- Tools for runtime tag management: `activate_capability`, `list_capabilities`
- Talents support frontmatter tag filtering — only load when relevant
- Reduces token overhead by keeping unused tools out of context

### Trust Zones
- First-class `trust_zone` attribute on contacts: `owner`, `trusted`, `known`
- Universal cost/priority router — gates email, compute allocation, proactive behavior
- Tools: `save_contact` accepts trust_zone, queryable via contact tools

### Model Routing Improvements
- `HintPreferSpeed` for delegates and non-interactive paths
- Quality floors: delegates (5/4), session summarizer (7), compaction through router
- Fixed `rulesMatched` accumulation bug across routing attempts
- Scheduled tasks support model and routing hint overrides

## Other Changes
