# v0.10.2 — The Native Home Assistant Release

v0.10.1 made the document substrate trustworthy — signed roots, verifiable provenance, an auditable history. v0.10.2 turns Thane outward, to the home — and it does so hand-in-hand with Home Assistant itself. HA 2026.7 shipped [*Automations that speak your language*](https://www.home-assistant.io/blog/2026/07/01/release-20267/): purpose-based triggers that describe intent (`light.turned_off`, `battery.became_low`) instead of entity plumbing, graduated from Labs to the default after eight months of work, plus `in_zones` presence and per-entity Visible boundaries. We embraced it wholeheartedly. This is the release where Thane's native `ha_*` toolset becomes the *complete* Home Assistant surface: the model can discover what it can call, debug what misfired, author automations in 2026.7's intent vocabulary, act across a whole area in one call, and read every entity in its owner's own words (`open`, not `on`) — and with native parity reached, the `ha-mcp` bridge is retired outright. Standing attention collapses into one loop-owned subscription model that follows the home as devices move and wakes a loop the moment state changes. The strong second story is the live conversation: a message that arrives mid-turn now folds into the turn already in flight, instead of getting a reply the next message already superseded.

## Home Assistant — native-first

**Home Assistant — native-first.** HA 2026.7 landed as the production release, and this milestone closes the last gaps between our native tools and the `ha-mcp` bridge — then removes the bridge. Native-first is no longer a preference; it's the only HA path that exists.

- **The model can finally discover what it can call, and debug what misfired.** `ha_list_services` turns HA's `/api/services` catalog into a real discovery surface with progressive disclosure — a bare call lists every domain and service name, a domain reveals full field schemas plus whether a service accepts a target block — so the model checks before guessing instead of burning a failed call to learn a name (#1177). `ha_automation_traces` completes the authoring loop the native family was missing: create → run → *inspect why*, projecting HA's step-by-step run record into execution order with triggers, condition results, and per-step errors, so a model authoring an automation can verify it actually behaves as intended (#1178).

- **"Turn off the office lights" is now one call with visible results.** `ha_call_service` had *hard-required* `entity_id`, making target-addressed calls impossible — the only fan-out paths were N individual calls or `ha-mcp`'s `ha_bulk_control` and its status-polling babysitter. Targets are now first-class: area/floor/label/device/entity selectors that resolve human names ("Office" → `office`) case-insensitively and fail fast with the known names on a typo, so an unknown `area_id` can't silently no-op. The response reports what actually changed — `changed_count` and the changed entity IDs — replacing the old `"Successfully called…"` string that reported nothing (#1179).

- **Automations are authored in HA's intent vocabulary, so they survive a device swap.** 2026.7 made purpose-specific triggers (`light.turned_off`, `battery.became_low`) the default — they target areas rather than entity IDs, so an automation follows the home as devices move. Our tools passed the new shapes through unchanged, but nothing *taught* them, so the model kept authoring 2024-style entity-state triggers that break the moment a sensor is replaced. `ha_automation_vocabulary` fetches the live purpose triggers/conditions/services for a target (integrations register their own, so it can't be hardcoded), and the create/update schemas plus the talent now present the intent form as primary with classic triggers as the documented fallback (#1176).

- **The tools now respect the operator's Visible boundary — and mirror HA's own device page.** HA's per-entity **Visible** toggle is the operator's declared boundary for assistants, but the discovery tools ignored it and returned hidden entities as if the operator had never spoken. `ha_search_states` and `ha_list_entities` now default to the visible set with an advertised `hidden_excluded` count (never a silent drop) and an explicit opt-in (#1185). Conversely, `ha_device` — where naming a device *is* intent to see its whole instrument panel — now groups entities into HA's own Controls / Sensors / Configuration / Diagnostic buckets by `entity_category` and shows hidden entities marked, so the model reads a device the way its owner does (#1186). Subscriptions gained the same "advertise, don't silently accept" discipline at authoring time: `add_entity_subscription` with an `area:`/`label:`/glob target now previews its live expansion and flags a zero-member match loudly, catching a typo'd `area:atrium` that would otherwise render nothing forever (#1193).

- **Every surface now speaks the operator's configured vocabulary, not raw on/off.** A prod bug the owner caught through the new tools: a garage-door binary_sensor configured "Show as: Garage Door" rendered as `on` instead of `open` because the enumeration and search tools emitted raw HA state while `ha_get_state` and the snapshots translated it. Both fixes route every entity-emitting surface through the shared class-aware projection — search/list (#1197) and the ambient state-change window injected *every turn*, which had been discarding the `device_class` attribute at dispatch (#1198). Person presence got the 2026.7 treatment too: a person in a nested zone (state names that zone, not `"home"`) was miscounted **away** until `in_zones` membership became the source of truth (#1181). The remaining coverage closed with event-entity projection (raw state is an ISO timestamp — exactly what the conventions forbid — now rendered as *what fired* plus a delta) and alarm-panel curation, with the full binary_sensor class table verified against current HA docs (#1186, #1205).

- **The ha-mcp bridge is retired.** Prod telemetry showed the model stopped reaching for the bridge on its own five weeks before anyone pulled the plug — native tools had organically displaced all six allowlisted MCP tools. The operator removed the server block from production config (killing the `uvx ha-mcp@latest` startup dependency and its supply-chain exposure), and the docs pass ensures new installs never learn the old path (#1180).

## Awareness & unified subscriptions

**One registry, one vocabulary, one tool family.** The agent's standing senses had grown organs faster than a skeleton — two data models, four tool families, a write-only storage tier, and a hardcoded ingestion floor invisible to the model. This cycle collapses all of it behind one idea: a subscription is loop-owned attention. Every subscription is now keyed by owner, and the tool surface converges so a single add/remove/list family covers concrete entities, globs, and loops alike.

- Retired the tag-scoped storage tier and the legacy spec-migration converter, replacing both with forward compilation — every spec write re-projects its subscriptions into the registry, a boot pass mirrors all definitions and sweeps orphans, so the model reasons over one declaration type instead of two stores that could silently drift (#1212, #1209).
- Made the person-entity ingestion floor visible: it was a hardcoded append inside the filter builder that `list_entity_subscriptions` couldn't see. It's now re-seeded as `system`-owned rows on every boot, so the list tool finally tells the whole truth — always-visible, loop-owned, and system rows, each carrying its owner (#1212).
- Settled the arc's last open decision by folding the anonymous always-visible tier into rows owned by `core` — the same thing the architecture always meant, since every context is ultimately core's. Legacy anonymous rows are cleared rather than migrated so the operator re-authors the production set by hand instead of carrying old choices forward mechanically (#1218, #1208).

**Subscriptions now speak the house's organization, and carry a macro-set lens.** A frozen device list ages the moment a sensor moves rooms; a subscription that tracks organization does not.

- Added `area:`, `label:`, and `floor:` targets whose membership is re-resolved from the registry every turn using HA's own inheritance rules — move a sensor into the office and an `area:office` watch picks it up with no re-authoring, the same follow-the-home durability 2026.7's purpose triggers gave automations (#1191, #1184).
- Added `requires_tag`: an entity renders only while its capability tag is active in the consuming context, so a dossier and its sensors arrive together when the macro set activates and fall away together when it doesn't — ownership answers who carries a subscription, the gate answers when it's worth the context tokens (#1214, #1213).

**Four feeds from one declaration — render, log, wake — each answering a different question.** The arc's payoff is that a subscription now declares not just what to watch but how it wants to be told, and asking is enough; capture is derived from the ask rather than configured separately.

- Added per-subscription transition logs (`transitions: n`, `transitions_window_seconds`): the entity's last n changes render inline as `{from, to, ago}` in the class-aware vocabulary — a garage bay reads closed→open, not off→on — answering "what just happened" beside the recorder-backed history summaries that answer "what has it been doing" (#1215, #1210).
- Added `wake: true`: when the watched entity changes, the owning loop is awakened with a `{entity, from, to, ago}` event — the feed the whole arc was building toward, so a loop can act the moment something changes without an MQTT hop for simple native triggers (#1217, #1211).
- Built both live feeds on the shared loopqueue chassis with wakestorm discipline born in, not retrofitted: changes enqueue durable, entity-deduped records that a debounced drain coalesces, so a chattering sensor becomes one wake carrying its freshest transition — never an iteration per flap — and `ago` is rendered at delivery so a record that waited out a debounce or survived a crash reports how stale it actually is (#1216, #1217, #1033).

**The ingestion filter became derived plumbing instead of frozen config.** Which entities' state changes feed the recent-changes window was declared in `homeassistant.subscribe` and frozen at boot; changing it meant a config edit and a restart.

- Made the state-watcher's ingestion filter a runtime registry that swaps under lock with no HA re-subscription, rebuilt on every mutation from the union of subscriptions that need the stream plus the system floor — so declaring a transition log or a wake automatically joins the target to capture, and `mode: ingest` demotes from a user-facing concept to derived infrastructure (#1206, #1215, #1192).
- Changed the empty-filter semantic deliberately: with nothing registered the filter now matches nothing, because under a runtime registry "empty means all entities" is a firehose default one removal away — the per-entity rate limit stays operator policy in config so a model can't raise its own wakestorm guard (#1206, #1024).

**The teaching pass shipped as a first-class deliverable, because the model is the user.** Six feature PRs had each appended their own bullet the way human docs accrete, leaving the most-traveled door stale.

- Fixed the severe case first: `thane_loop_create` still said in three places that entities "do NOT wake the loop" two days after `wake: true` on those same entities became the primary trigger — a stale door that would route a model to wire an MQTT automation for a case one field now covers. The trailhead was restructured from nine accreted bullets into the arc's actual decision frame (who carries it, what it feeds, what it costs), and `docs/model-facing-tools.md` gained a "the model is the user" section naming the two failure modes so the next arc doesn't repeat them (#1219, #1208).

## Live conversation — mid-turn delivery & observability

A long, tool-heavy turn used to answer whatever message kicked it off, blind to anything that landed while it worked — so a follow-up that superseded the request got a stale reply, and a durable loop launched from a Signal turn could silently die the moment that turn ended. This release closes the mid-turn delivery arc end-to-end and then makes the merge legible on every operator surface.

- **A message that arrives mid-turn now merges into the live turn.** A durable loop mailbox backed by `loopqueue` gives conversation inputs a durable, peekable home — Signal dispatch enqueues before it sends read receipts, so a burst from one sender no longer blocks the shared receive path or risks loss in a volatile in-memory channel. On top of it, a `PullInput` engine seam polls for new input at two points (the top of each iteration after a tool pair closes, and once more when the model is about to finalize a text-only reply), folding a late arrival into the same turn so Thane stops shipping answers the next message already superseded. Delta-gating never re-presents a message, and a per-turn drain budget (default 8) keeps a turn under continuous inbound flow terminating (#1220, #1221).

- **Loops launched from a Signal turn stay up.** `Registry.Launch` handed the caller's request context straight to a detached loop's run goroutine, so `loop_definition_launch`, `spawn_loop`, and `thane_assign` bound the loop's whole lifetime to the interactive turn that spawned it — it died mid initial-sleep the instant the turn ended, at `iterations=0`, after the model had already reported success. The committing verbs survived only because they reconcile on a detached context. Detached operations now derive their run context with `context.WithoutCancel`, severing the caller's cancellation while preserving request-scoped values; `request_reply` launches still propagate cancellation. This is the root cause behind "prod loops won't stay up" — production `ranch_climate_watch` was a casualty (#1224, #1225).

- **The model is taught the new mid-turn contract, and the doctrine gaps the outage exposed are closed.** A live channel loop can now receive the counterparty's words mid-turn, so the `message_channel` talent teaches what an arrival looks like, when to fold it in versus re-plan versus ignore it, and what not to do (don't restart the turn, don't tear up a tool batch) — scoped to the live-channel tag rather than the global contract so background loops aren't told about a capability they lack. Separately, the loops talents now teach that tags carry a knowledge bundle, not just a tool surface (a broad capability tag like `ha` leaks a doc into every loop that activates it), and that a running loop keeps the config it launched with — scalars retune live, structure binds at launch and needs a relaunch (#1222, #1226, #1228).

- **The mid-turn merge is observable end-to-end, not reconstructed from a retained prompt.** Confirming a real merge used to mean spelunking a 47-message request array for a render-layer marker string. Now the arrival, the merge, and the tally each emit structured `Source: loop` events that the SSE feed and the archive pick up with no extra wiring: `loop_mailbox_arrival` when a message lands while a turn is in flight, `loop_midturn_input` on each delivering pull, and a `midturn_merged` tally on `loop_iteration_complete`. The arrival event gates on an active conversation id rather than the loop's state enum, so it never fires with an empty id during post-turn teardown or startup (#1230, #1232, #1233).

- **Mid-turn injection is a first-class flag, not a substring match.** A mid-turn-merged user message was persisted as a plain user message, so any consumer had to substring-match channel-specific render prose that had already been reworded once — the exact fragility flagged in the #1229 review. A structured `mid_turn` flag now rides the message record via an additive migration, surfaces on `/v1/conversations/{id}`, and reads through `COALESCE` so a legacy NULL row can never silently drop from the transcript (#1235).

- **The web console renders the merge on the live-turn timeline.** A completed turn shows a "folded N messages" badge from its tally; a live turn shows each message arriving and merging in real time, styled as continuity rather than tool activity. The badge is seeded into the persisted iteration snapshot too, so a client that reloads or joins late sees the same history a live watcher saw instead of a badge that vanishes on refresh (#1236).

## Context & memory robustness

An audit of the prompt Thane actually ships per turn, plus two production incidents, converged on one theme: the context layer was doing too much, saying it twice, and — worst of all — sometimes freezing without a sound. This release tightens all three, and closes the production symptom of "trouble holding a coherent conversation."

- **Working memory no longer freezes on short-message runs.** `GetMessages` — the single source of per-turn history — was returning the *oldest* 100 active rows instead of the newest, an ordering bug that stayed invisible only as long as compaction kept the active set under 100. But compaction was token-gated only, so a long wind-down of brief back-and-forth texts pushed the row count past 100 while tokens stayed low, and the model's context froze at the 100th-oldest message while new turns kept inserting — presenting as confident, hallucinated replies from a conversation that had already moved on. The read now returns the newest window unioned with active summaries, compaction gained a count-aware trigger (prod: 80 rows, 20 rows of headroom under the read window), and a rate-limited warning fires whenever the window clips — because the 45 minutes of silent amnesia in prod is exactly what the old code never reported. The read-side fix heals an already-frozen conversation on its next turn, no migration (#1231).

- **Compaction stopped corrupting the histories it exists to protect.** A live conversation was found with 7 of 27 messages being duplicate `[Conversation Summary]` blobs, some interleaved mid-dialogue, plus an orphaned reply whose question had been compacted out from under it. Four compounding defects, each independently wrong: concurrent fire-and-forget compactions raced during the 30–90s summarize call (fixed with per-conversation single-flight); summaries inserted as `role='system'` were never re-compacted, so they stacked forever and re-armed the trigger (now folded into one summary per pass); summaries stamped with `now()` landed between a message and its reply (now stamped with the folded region's earliest timestamp so they sort to the head); and a wall-clock cutoff swept up rows written mid-compaction (now an exact ID-set with turn-edge snapping). The aggravator — an 8,000-token hardcoded ceiling that compacted conversations that never should have been — is now `compaction.max_tokens`, defaulting to 32,000 (#1168, #1170).

- **The system prompt stopped shipping a second copy of the conversation.** An ordinary Signal turn carried a 30.7KB verbatim transcript of history the model had *just received* as role-native messages, re-encoded under a nonstandard `"past you"` role — plus a 25.8KB older-sessions block, six of whose twenty entries were empty rotation noise. The verbatim tail is removed outright (stored history already reaches the model role-natively, and the block's delta timestamps had made the whole prompt prefix permanently uncacheable), and the older-sessions catalog is now curated: empty sessions filtered, cap dropped 20→5, ceiling 16KB→8KB, with truncation now always signaled rather than silent (#1160, #1164).

- **Delta timestamps became humane, and provider framing stopped drifting.** The prompt was full of six-figure second counts like `"-460301s"`, forcing the model to do `÷86400` arithmetic on every session catalog, contact age, and loop view; deltas now render tiered (exact seconds under an hour, `-26h45m`, `-5d9h`), and the parser round-trips them back so models can copy displayed deltas straight into tool arguments. Alongside, per-provider drift was swept: editor-voice framing rewritten to plain scope statements, forge/companion payloads given `### Heading` boundaries to match their siblings, and channel-overview ordering now sorted locally instead of trusting an unenforced upstream contract that could silently churn prompt bytes (#1160, #1165, #1166).

- **LM Studio stopped 400ing on pure-tool-call turns.** The lmstudio adapter omitted the `content` field entirely for messages with no text — assistant turns carrying only `tool_calls`, and empty tool results — and LM Studio's OpenAI-compatible endpoint rejects a message with no `content`. It surfaced intermittently (only when a turn's tool call arrived without accompanying text) once the qwen bench arm began routing through lmstudio; the ollama adapter had always set `content` unconditionally, which is why the gpt-oss arm never hit it. The adapter now always emits `content`, matching ollama (#1229).

## Document substrate & checkout

**Document substrate & checkout.** Local Git working trees became a shared platform primitive. Signed document roots, forge mirrors, and core identity used to each assemble their own Git plumbing; this release consolidates that into one checkout layer and, on the back of it, closes two long-standing operator gaps — reading followed repositories and trusting what a document-write tool reports.

- **A shared checkout primitive now backs every local working tree.** The neutral mechanics of a signed-or-verify-only checkout — resolving the repository/worktree relationship, mapping root-relative paths, opening provenance stores, reconciling trust, driving remote sync and its state — moved into `internal/platform/checkout`. Document roots kept their policy (transition classification, index refresh, wake notifications) but stopped hand-rolling the Git machinery, so the next consumers inherit a proven path instead of growing a parallel one. Core identity bootstrap folds in through a deferred hatch that lets it write its own signed birth commit, retiring the last provenance-shaped clone path (#1155, #1156, #1157, #1158, #1163).

- **Followed forge repositories now maintain a local checkout a loop can read.** `forge_repo_follow` accepts a `local_checkout` path and keeps it as a read-only mirror on the shared rail — fetch, reset, scrub — supplying the transport URL only to the git command so no credentials persist in `.git/config`. Each poll refreshes the tree before waking the target loop and tells it exactly which checkout and SHA it now reflects, and unfollowing leaves the tree on disk. Point that path under `workspace.path`, declare it as a read-only root like `thanecode:` with indexing off, and loops navigate real code through `file_read`/`file_search`/`file_grep` — the piece that made repository subscriptions actually useful rather than event-only (#1032, #1159, #1161, #1162).

- **Doc-root sync trouble now wakes the core loop instead of nagging a human channel.** Refusal states — `blocked`, `diverged`, `remote_behind` — and clean recovery are detected as transitions and routed through the loop message bus as system-originated core-attention wakes, sharing the target resolver with `request_core_attention`. Sync workers start only after durable loop definitions reconcile, so the configured attention target exists before the first sync pass fires (#1151, #1154).

- **`doc_write` can no longer silently eat content sent under the wrong parameter name.** A prod incident had the archivist send a full dossier as `content` + `mode` (doc_edit's vocabulary); `doc_write` ignored the unknown keys, wrote a frontmatter-only file, and returned success — phantom completion, same failure class as #1103's `parent_name`-in-metadata. The fix removes the trap rather than fencing it: the whole document surface now shares one `body` vocabulary, the legacy `content` key gets a rename-teaching error on both tools (so replayed history can't apply an empty edit), and a store-level guard rejects any bodiless create — catching future vocabulary drift regardless of key name (#1201, #1202).

- **`doc_create` puts the duplicate-collision check on the create verb itself.** The COTA-weekend near-duplicate slipped through because the safety analysis lived on `doc_intake`, a side door, while the model's real impulse — *make this document exist* — reached for a create verb that wrote unchecked. `doc_create` runs the corpus-aware intake analysis and writes when placement is clean; when the corpus pushes back it writes nothing, returns `created: false` with an `intake_id`, and `doc_commit` finishes deliberately. `doc_write` keeps create for known destinations but its description now steers anything brand-new toward `doc_create` — shaping the channel instead of relying on willpower (#1038, #1204).

## Operational hardening

**Operational hardening.** The quiet-but-load-bearing changes: a wedged turn now recovers on its own, the loop graph reads straight, and the surfaces the model and the operator depend on stay honest.

- **A subprocess timeout can no longer hang the turn behind it.** In the 2026-07-02 incident an `exec`-launched `find /` hit its 60s deadline, but killing `sh` orphaned a grandchild that kept the inherited output pipes open — so the tool call never returned, the goroutine leaked, and the owner's Signal message went unanswered for as long as `find` cared to run. `exec` now runs the command in its own process group and kills the whole group at the deadline, with a 5s `WaitDelay` backstop that abandons the pipes for anything that still escapes; output captured before the deadline is preserved either way (#1167, #1169).
- **The loop graph no longer hangs six service loops off `core`.** `unifi-poller`, the email and media pollers with their default-handlers, and the forge subscription poller sat directly under `core` while every other loop already gathered under a container, leaving the graph lopsided. A new `pollers` grouping container gives them a home; it's gated to appear only when a member integration is enabled, with shared predicates driving both the container and its members so they can't drift into an empty container or an orphaned loop (#1035, #1237).
- **Two model-facing surfaces became typed contracts instead of runtime accidents.** `loop_containers` and the placement advisory built their output from untyped maps whose field names and presence were free to drift the moment someone edited them without realizing they were a schema; they now carry declared structs with per-field Godoc and wire-shape golden tests, so a silent model-facing change becomes a test failure — with byte-identical output at introduction so the model never notices (#1173, #1207).
- **Pre-release audit cleanups.** The v0.10.1 Godoc and model-facing sweep fixed seven under-documented types (deepest: `ProjectSubscription`'s 18 fields) and renamed `doc_at`'s revision timestamp from `as_of` to the `timestamp` the sibling revision tools already use, so the model learns one name for one concept; a flaky knowledge-store truncation test was pinned to deterministic timestamps; and the release checklist was streamlined and audited so every remaining item earns its place (#1174, #1203, #1238).

## Upgrade Notes

**One config key now fails loudly at boot: `homeassistant.subscribe`.** It was retired deliberately — silently ignoring it would let a deploy quietly change behavior — so Thane refuses to start until it's gone. This is the only config-schema breaking change this cycle. State-change capture now derives from the subscription registry (ingest / transitions / wake subscriptions plus `person.track`), so the old `entity_globs` no longer feed the ingestion filter. Delete the `subscribe:` block, move its `rate_limit_per_minute` to `homeassistant.ingest_rate_limit_per_minute`, and re-declare any globs you still want as `mode: ingest` subscriptions after boot. (#1192, #1206)

**The always-visible subscription tier starts empty.** The unification clears the legacy anonymous rows rather than migrating them, so after first boot re-author the production set by hand as `core`-owned subscriptions — until you do, those entities aren't ingested. Watch the orphan-sweep and the new per-subscription transition logs to confirm capture resumed. (#1218, #1208)

**Home Assistant must be running 2026.7.** The native `ha_*` tools target 2026.7's purpose-specific triggers, `entity_category` grouping, and `in_zones` presence. Upgrade the HA install before or alongside this deploy.

**Remove the `ha-mcp` server block from config.** The native tools have fully displaced the bridge. Removing the block kills the `uvx ha-mcp@latest` startup dependency and its supply-chain exposure. (#1180)

**Backport the updated talents to any live `talents_dir`.** Prod loads talents live from an unsigned, hand-edited `talents_dir` that the deploy does not touch. The `message_channel` and loops talents changed this cycle (mid-turn contract, `wake: true` teaching, tags-carry-knowledge) — copy the updated repo `talents/` files into the production talents directory so the model learns the new doors. (#1219, #1222, #1226)
