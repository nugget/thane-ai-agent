# v0.9.2 - The Context Integrity Release

v0.9.2 is the release where Thane gets serious about context integrity.
v0.9.1 made the operational surfaces sturdier; v0.9.2 asks the next, harder
question: can the model trust the context it sees, understand why it is seeing
it, and delegate work without carrying the wrong state across boundaries?

The answer is now much closer to yes. Documents gain signed roots and
corpus-aware intake. Capability tags become additive, inspectable, and tied to
live context. Delegates get task-shaped prompts, sharper lifecycle verbs, and
recursion guards that survive the launched-loop path. Model-facing outputs move
toward compact JSON and exact-second deltas. Anthropic telemetry stops hiding in
provider internals and starts showing up where operators can reason about
capacity, cache behavior, and stop reasons.

**695 files changed, 34,938 insertions, 15,491 deletions.**

## Trustworthy Document Roots

The largest theme in this release is that durable knowledge now has a stronger
chain of custody. Generated documents carry provenance metadata such as who
created them, when they were generated, what kind of document they are, what
sources shaped them, and whether they live under a managed root (#768).

Managed document roots are now a real policy surface. Roots can define authoring
policy, indexing policy, signature expectations, and verification intent (#771).
Read-side enforcement now honors those policies: roots marked as required fail
closed when content is unsigned, untrusted, or unverifiable (#773). New or empty
roots can be bootstrapped with a signed birth commit (#791), and trust is now
anchored in a repo-local `.allowed_signers` file instead of a wider config knob
(#796).

The configuration model was cleaned up around this. `roots:` is now the
canonical shape for workspaces and document roots, replacing the older split
between `paths:` and `doc_roots:` while still giving legacy configs a migration
path (#792). The bypasses were tightened too: file tools, talents, and injected
files verify protected-root reads, and raw file mutation is blocked inside
protected document roots (#793).

Document authoring also became more deliberate. `doc_intake` and `doc_commit`
now provide a corpus-aware path for promoting content into durable knowledge,
including nearby documents, tag overlap, and recommendations before committing
new material (#774). Loop specs can declare document outputs directly, which
generates scoped append/replace tools for those outputs instead of letting loops
write arbitrary files (#770). The ego loop now uses that loops-ng substrate
instead of the older scheduler-driven periodic reflection path (#801).

## Capability-Scoped Context

This release reshapes how Thane decides what context belongs in front of a
model. Contact origin policy gives sessions a typed sense of where a message
came from, and contacts can carry origin tags and context references (#754).
The `message_channel` capability now gets structured, verbatim recent-message
tail context instead of the old LLM-driven session carry-forward mechanism
(#762). Knowledge-base articles also gained `tags_all`, making it possible to
require tag intersections such as owner plus channel rather than relying only on
OR-style matching (#763).

Context assembly now flows through one provider pipeline. KB articles, tagged
providers, and always-on providers share one cap and one order of operations
(#785). Delegates suppress ambient always-on context by default, so child loops
receive the task-relevant context they asked for without inheriting the entire
operator room tone. Core identity and injected files moved into the same
provider model, with prompt modes for `full` and `task` context (#797).

Capability tags also became clearer and more inspectable. Native tools now
self-declare tags, MCP tools use tags from configuration, and overlays are
additive include/exclude rules rather than replacement lists (#798). The old
`tools` and `default_tags` shapes now hard-error so misconfiguration is loud.
Operators also get new visibility through `inspect_capability`, `/api/capabilities`,
and `thane caps` (#798). Loop tag state was simplified so `Spec.Tags` is the
source of truth, including MQTT wake migrations (#813), and the dashboard now
surfaces loop tag forensics consistently with runtime state (#832).

## Delegates and Loop Intent

The delegate surface now reads like the lifecycle it represents. The old
catch-all `thane_delegate` path was replaced by the `thane_*` family:
`thane_now`, `thane_assign`, `thane_curate`, and `thane_wake` (#784). Those
verbs make it clearer whether work is immediate, backgrounded, curatorial, or a
wake-up. The deprecated shim is now gone, and orchestrator defaults point at the
live verbs directly (#843).

The loop API underneath was cleaned up at the same time. `LoopOptions` replaces
long chains of setters with grouped configuration (#784), delegate docs now map
the current lifecycle more accurately (#825), and the tag-system narrative has
been rewritten around the current architecture (#834).

The recursion guard also got its real production fix. The first guard stopped
the obvious nested `thane_*` calls (#828), but production showed a second path:
the launched-loop catalog could rebuild tools and reintroduce the delegate
family. Request-level exclusions now survive that path, and child launch errors
surface the child loop's `LastError` instead of collapsing into an empty joined
error (#833). Production-tuned talents were backported into the repo and
embedded defaults after the new patterns proved out live (#837).

## Model-Facing Honesty

Several changes are about giving models less ambiguous context. Archive tools
now return structured JSON, exact-second deltas, and an explicit `archive_range`
(#761). Archive search no longer returns empty results just because a context
window exceeded the byte cap (#764), and archived assistant messages are labeled
as `"past you"` so the model can distinguish its current voice from prior
utterances (#765).

Timestamps keep moving toward relative, exact deltas. Conversation history uses
`age_delta` instead of raw timestamps (#827), curated document frontmatter
normalizes legacy timestamp aliases into model-friendly deltas (#829), and
prompt/tool output cleanup removed several remaining raw timestamp and noisy
shape leaks (#794). Channel context now renders as a stable JSON envelope
instead of prose that callers had to mentally parse (#831).

Home Assistant context also got sharper. Watchlist rendering is now
device-class-aware, includes structured availability, remembers last-known-good
state, and adds device, integration, gateway, and area activity context (#795).
Direct HA tools and awareness now share the same richer formatter (#803).
Weather entities can subscribe to forecasts (#814), and forecast truncation or
provider failure is now explicit in the model-facing result rather than implied
by missing rows (#830).

## Provider Operations

Anthropic behavior is much easier to inspect in this release. Cache-control
markers can be debugged outbound (#800), provider clients now receive the
dataset logger late enough to capture the right call path (#802), and tool
definitions are sorted by name to stop Go map iteration from invalidating prompt
cache hits (#804).

Usage records now capture Anthropic request IDs (#807), rate-limit headers and
cache-marker drop reasons (#808), and stop reasons on both `ChatResponse` and
iteration records (#809). Streaming usage aggregation picked up a regression
test (#810), and the router stats/dashboard system view now exposes the latest
Anthropic rate-limit snapshot (#811).

## Under the Hood

The internal package layout was reorganized around runtime, model, state,
channels, integrations, and platform boundaries (#755). The model fleet package
was renamed into its current shape (#756). `thane init` now bootstraps a core
identity root with an SSH signing key, channel CA, and signed birth commit
(#757). Legacy paths were retired (#782), catalog registrations were filled in
for the newer document/archive tools (#783), and SQLite dependencies were
refreshed for the release (#805, #806).

The release machinery got cleaned up too. The checklist now follows the actual
cut flow (#815), and the 0.9.2 candidate pass added the final RC checks around
config drift, generated notes, notarization status, release assets, and
post-release verification (#845).

## Upgrade Notes

1. `roots:` is the canonical configuration shape. Legacy `paths:` and
   `doc_roots:` configs can migrate, but mixed shapes are not supported (#792).
2. Document roots with required signature verification now fail closed. Make
   sure each protected root has a committed `.allowed_signers` file and valid
   signed history before restart (#773, #791, #796).
3. Raw file tools no longer bypass protected document roots. Use the managed
   document tools and declared loop outputs for protected-root writes (#770,
   #793).
4. `thane_delegate` has been removed. Production configs, talents, prompts, and
   orchestrator tool lists should use `thane_now` and `thane_assign` instead
   (#784, #843).
5. Capability-tag config is now additive. Replace legacy
   `capability_tags.<tag>.tools` with `include`/`exclude`, and replace MCP
   `default_tags` with `tags` (#798).
6. The old scheduler `periodic_reflection` path has been replaced by the ego
   loops-ng service (#801).
7. Model-facing consumers should expect more structured JSON, `age_delta` /
   delta fields, explicit forecast truncation fields, and richer HA context
   envelopes (#761, #795, #827, #830, #831).

## Release Posture

This is the strongest 0.9.x build so far, but it is intentionally stricter than
0.9.1. The two things to review before production rollout are protected document
root trust state and any lingering references to `thane_delegate` in local
config, talents, or operator-authored prompts. The new inspection surfaces
(`thane caps`, `inspect_capability`, `/api/capabilities`, and the dashboard tag
forensics view) are the quickest way to verify that runtime context matches your
intent after upgrade.
